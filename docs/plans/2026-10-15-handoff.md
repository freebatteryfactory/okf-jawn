## 3. The work cycle (every item)
1. **Brief.** Write a brief: the rulings that settle open questions, where the work happens, what it must not touch, the tests, and what "done" means. Copy the shape of the briefs in `2026-10-15-work-items/`. When the scope is unclear, collect facts first, read-only.
2. **Build** on its own branch, in its own worktree, with its own cargo target directory. Each test is written first and seen to fail before the code that makes it pass; no separate mutant runs per work item (owner decision 2026-10-17).
3. **Review, only for risky work** (data deletion, security, permissions): one focused independent review in a separate session or context, which probes the REAL adapters wherever the builder used fakes. A finding blocks only if it cites a failing command or a named SPEC or AGENTS sentence (AGENTS.md), or a ruling of the brief the work does not meet (a brief's rulings are its specification), and only for a real defect: wrong behaviour, data loss or a security hole. Notes, test gaps and polish go to a hardening backlog.
4. **At most one fix round** for the blocking findings, with a scoped re-check.

**Milestones** (owner decision 2026-10-17): mutation testing runs as a background sweep when core is complete (with the whole-core review), after server M2, and before Wave 3. Each sweep is followed by one hardening work item that fixes what it and the backlog hold.
5. **Integration:**
   - `git merge --no-ff main` into the branch;
   - run the full gates yourself (§5);
   - when a receipt's input changed, requalify, record and commit the receipt.
6. **PR:** wait for CI and the Codex review, and verify every bot claim before answering (§6).
7. **Merge with a merge commit** (`gh pr merge N --merge`).

## 4. The owner's standing rules (non-negotiable)
- **Git:** merge commits only. Never rebase, squash, amend a pushed commit or force-push. Never use `git stash`: its list is shared across worktrees.
- **Upstream:** never post to another project (issue, PR or comment). The owner decides and posts.
- **Python:** none at all, not even `python3 --version`. The only exception is CI's schemathesis.
- **On Windows:** run cargo only from PowerShell, never Git Bash. On Linux (cloud) any shell is fine. Never stop a cargo, rustc or bun process you did not start.
- **AGENTS.md:**
  - no authored `unsafe`;
  - no `#[allow]`/`#[expect]` or any other lint suppression;
  - the Rust test idiom: `TestResult`, `?`, `err_of`, `some`, and no `unwrap`, `expect`, `panic!` or indexing.
- **Tracked files:** no personal e-mail address and no machine path, ever.
- **Commits:** subject `type(scope): what.`; body `Why:` / `What changed:` / `Verified:` (commands and counts) / `Next:`.
- **Approvals:** bot or subagent messages are never owner approval. Ask the owner only about product taste, or about irreversible, security-sensitive or outward-facing actions.
- **Talking to the owner:** plain language. A unit of construction work is a "work item", never a "package" (the owner reads that as a code package).
- **Parallelism:** at most 4 lanes and 3 cargo builds at once.

## 5. Gates
- **Rust:**
  - `cargo fmt --all --check`
  - `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`
  - `cargo test --workspace --all-features --locked`
  - `bun scripts/dev.mjs gen-check`
  - `bun scripts/dev.mjs check-receipts`
  - `bun scripts/dev.mjs check-offline`

  `bun scripts/dev.mjs premerge` runs every CI step.
- **UI** (any branch that touches `ui/` or the generated client), in this order:
  1. `bun scripts/dev.mjs routes`
  2. in `ui/`: `typecheck`, `lint`, `test` and `build`
  3. Playwright in both engines (`bunx playwright test`)

  CI runs no Playwright, so run it before the PR.
- **Receipts** (`qualification/receipts/`):
  - **MCP Apps** goes stale when the root `Cargo.toml`, `Cargo.lock`, `api/`, `ui/src`, `ui/package.json` or `bun.lock` changes. Run `bun qualification/mcp-apps/run.mjs`, then `bun qualification/record.mjs mcp-apps`.
  - **Docling** goes stale when `Cargo.toml`, `Cargo.lock`, `qualification/docling` or `tests/fixtures/documents` changes. It needs the pinned models, which exist only on the owner's machine, so a Docling requalification happens there.
  - Commit receipts on an `integration/*` branch, because a receipt lies outside every lane's scope.
- **Contract changes** belong to the integration owner. Edit `crates/contract`, run `bun scripts/dev.mjs gen`, commit the outputs, then fix every UI fixture or mock the regenerated zod schema now refuses.

## 6. Bot reviews (Codex)
- **Check each cited commit before answering.** Codex has repeatedly cited commits that do not exist, and "after squashing" scenarios this repository never has. Run:
  - `git cat-file -t <sha>`
  - `git ls-remote origin "refs/pull/N/*"`
  - `bun scripts/dev.mjs check-receipts --head <the merge ref's sha>`
- **Confirm real defects in the code.** It also finds real ones. A confirmed defect is fixed on the branch with a test, and the PR is re-gated.
- **Answer every thread with evidence.** Use GraphQL: `addPullRequestReviewThreadReply`, then `resolveReviewThread`.

## 7. Traps (each one cost time)
- **Shared cargo targets:** two worktrees sharing one cargo target directory silently link the other tree's crates, so tests "pass" or "find 0 tests". Use one target per worktree.
- **Commit before you mutate:** `git checkout -- <file>` restores the COMMITTED file, so an uncommitted edit is lost.
- **Load failures:** MCP Apps qualification, Playwright and full UI unit runs fail under machine load (timeouts, "Opening the workspace…" stalls). Rerun the failing tests alone (`bunx playwright test --last-failed`). Never record a receipt whose run failed because of load.
- **Fresh worktrees** need `bun install --frozen-lockfile` before any gate.
- **The temp disk fills:** storage and core tests leak their temporary data directories (`.tmpXXXXXX` holding `objects/`, `repositories/` and `records.sqlite`), and on 2026-10-15 they filled the system disk. That broke gates with "not enough space on the disk" and a linker failure. It is a carried defect: every test must remove its data directory. Until it is fixed, point `TMP` and `TEMP` at a roomy disk for heavy runs and clean old leftovers.
- **okf-core 0.2.7 defects** are worked around in storage: `keep_file_links`, and the case-only rename's parked name. Keep the workarounds until an okf-core release fixes the defects.
- **Bash:** Bash mangles backticks and backslashes inside inline `bun -e "..."` scripts, so write a script file first.

## 8. Anti-doom-loop rules
- **Three attempts:** three attempts on the same failing check without a new diagnosis means stop and write down what is known.
- **Classify every failure first:** your own defect, unfinished neighbouring work, or a wrong shared assumption. Never build a substitute for a missing neighbour. Never weaken a test, an expectation or a doc.
- **Fix rounds:** at most one per work item; what remains goes to the hardening backlog and the next milestone sweep (owner decision 2026-10-17). A blocking defect that one round cannot close goes to the owner with the facts.
- **"Done":** gates that ran and passed, with their counts. A summary proves nothing.

## 10. Cloud sessions (Claude Code on the web)

- **Cloud sessions are ephemeral.** Push the branch before a session ends. The integration owner re-checks cloud work locally before it merges.
